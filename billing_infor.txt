Required Stripe events to subscribe on the webhook endpoint:
- checkout.session.completed
- customer.subscription.updated
- customer.subscription.deleted
- invoice.paid
- invoice.payment_failed
(Optional: checkout.session.expired)

Serverless endpoints:
1) POST /api/create-checkout-session
- Requires Authorization: Bearer <Supabase access token>.
- Validates token via supabase.auth.getUser(token) using SUPABASE_SERVICE_ROLE_KEY.
- Uses STRIPE_SECRET_KEY and STRIPE_PRICE_ID_MONTHLY/STRIPE_PRICE_ID_YEARLY env vars.
- Creates Stripe Checkout Session (mode=subscription) with:
  - client_reference_id = user.id
  - customer_email = user.email (optional)
  - metadata.supabase_user_id = user.id
  - metadata.plan = monthly/yearly
  - IMPORTANT: also ensure subscription metadata includes supabase_user_id (so subscription.updated/deleted can map to user).
- Returns { url: session.url }

2) POST /api/stripe-webhook
- Verifies Stripe signature using raw request body (must not JSON parse before verification).
- Uses STRIPE_WEBHOOK_SECRET env var.
- Updates entitlements row based on:
  - checkout.session.completed -> retrieve subscription, set entitlements paid if status active/trialing.
  - customer.subscription.updated/deleted -> set entitlements paid/free based on subscription status; for strict downgrade, deleted => free immediately.
  - invoice.paid / invoice.payment_failed -> retrieve subscription and sync entitlements accordingly.
- Must map Stripe events back to user_id:
  - Prefer subscription.metadata.supabase_user_id
  - Fallback: entitlements lookup by stripe_subscription_id or stripe_customer_id

3) POST /api/create-portal-session
- Requires Authorization: Bearer <Supabase access token>.
- Looks up stripe_customer_id from entitlements for user_id.
- Creates Stripe Billing Portal session:
  - return_url = https://www.promptschola.com/pricing.html
- Returns { url: portalSession.url }
